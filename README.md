# Массовое включение персональной 2FA в Яндекс 360

`y360_per_user_2fa.py` выгружает сотрудников организации в CSV, позволяет администратору удалить ненужные строки и массово включает обязательную двухфакторную аутентификацию оставшимся пользователям.

Скрипт работает на Windows, macOS и Linux, использует только стандартную библиотеку Python и не требует установки пакетов через `pip`.

## Важное условие

Персональное назначение работает только при включенной обязательной 2FA v2 в режиме `scope=per_user`. Скрипт проверяет режим перед выгрузкой и перед применением CSV. Он не переключает организацию автоматически.

Для явного включения режима предусмотрено отдельное действие `domain-enable` с контрольной фразой. По умолчанию оно не завершает пользовательские сессии.

Функция доступна только в тарифах для крупных организаций «Корпоративный + Безопасность» и «Корпоративный Максимум».

## Что реализовано

- Выгрузка пользователей страницами по 1000 записей.
- Отдельные этапы `export` и `apply`: терминал можно закрыть между этапами.
- Интерактивный режим: выгрузка, ожидание редактирования CSV и применение.
- В CSV сохраняются `UID`, логин и основной email.
- Повторная сверка `UID` ↔ `login` ↔ `email` с актуальным справочником.
- Проверка, что в организации включен v2-режим `per_user`.
- `--dry-run` для полной предварительной проверки без изменяющих PATCH-запросов.
- Контрольная фраза с точным числом пользователей.
- До четырех параллельных запросов по умолчанию.
- Повторы при `429`, `500`, `502`, `503`, `504` и сетевых сбоях.
- Ошибка одного пользователя не останавливает остальных.
- Итоговый CSV-отчет по каждой строке.
- Опциональная проверка результата отдельным GET-запросом `--verify`.
- Возможность тем же CSV массово выключить персональную 2FA через `--state disable`.

## Методы API

- Статус и режим 2FA организации: `GET /security/v2/org/{orgId}/domain_2fa`.
- Включение 2FA v2: `POST /security/v2/org/{orgId}/domain_2fa`.
- Список сотрудников: `GET /directory/v1/org/{orgId}/users`.
- Изменение персональной 2FA: `PATCH /directory/v1/org/{orgId}/users/{userId}/domain_2fa?is2faEnabled=true`.
- Проверка персональной 2FA: `GET /directory/v1/org/{orgId}/users/{userId}/domain_2fa`.

## Требования

- Python 3.10 или новее.
- Учетная запись администратора организации Яндекс 360.
- OAuth-приложение с разрешениями:
  - `directory:read_users` — просмотр сотрудников;
  - `directory:write_users` — изменение персональной 2FA сотрудников;
  - `ya360_security:domain_2fa_write` — просмотр и управление обязательной 2FA организации.
- OAuth-токен, полученный администратором организации.

## Подготовка

Положите `y360_per_user_2fa.py` в отдельную папку. Токен и ID организации задайте через переменные окружения или файл `.env` рядом со скриптом.

Содержимое `.env`:

```dotenv
OAUTH_TOKEN=y0__фактическое_значение_токена
ORG_ID=1234567
```

Не добавляйте токен и рабочие CSV в Git. Готовый `.gitignore` уже включен в комплект.

### Windows PowerShell

```powershell
$secureToken = Read-Host "OAuth-токен" -AsSecureString
$env:OAUTH_TOKEN = [System.Net.NetworkCredential]::new("", $secureToken).Password
$env:ORG_ID = Read-Host "ID организации"
python .\y360_per_user_2fa.py --help
```

### Windows CMD

```bat
set /p OAUTH_TOKEN=OAuth-token:
set /p ORG_ID=Organization-ID:
python y360_per_user_2fa.py --help
```

### macOS и Linux — Bash

```bash
read -rsp "OAuth-токен: " OAUTH_TOKEN; echo
export OAUTH_TOKEN
read -rp "ID организации: " ORG_ID
export ORG_ID
python3 y360_per_user_2fa.py --help
```

## Шаг 1. Проверить режим организации

Windows:

```powershell
python .\y360_per_user_2fa.py status
```

macOS и Linux:

```bash
python3 y360_per_user_2fa.py status
```

Для массового назначения ожидаются:

```json
{
  "enabled": true,
  "scope": "per_user"
}
```

Если режим еще не включен, его можно настроить в Кабинете организации или отдельной командой:

```powershell
python .\y360_per_user_2fa.py domain-enable --duration 86400 --no-logout-users
```

Здесь `86400` — сутки, в течение которых пользователь может отложить настройку второго фактора. Значение `0` не дает отсрочки.

Перед POST-запросом скрипт покажет текущую настройку и потребует ввести контрольную фразу. Не добавляйте `--logout-users` без согласованного окна изменений: при завершении сессий пароли приложений потребуется создать заново.

## Рекомендуемый сценарий: два этапа

### 1. Выгрузить пользователей

Windows:

```powershell
python .\y360_per_user_2fa.py export --exclude-dismissed --exclude-disabled --exclude-robots
```

macOS и Linux:

```bash
python3 y360_per_user_2fa.py export --exclude-dismissed --exclude-disabled --exclude-robots
```

Будет создан файл вида `users_2fa_1234567_20260909_120000.csv`.

CSV содержит три столбца:

- `UID` — идентификатор сотрудника;
- `login` — логин сотрудника (`nickname` в API);
- `email` — основной адрес сотрудника.

Файл записывается в UTF-8 с BOM и с разделителем `;`, поэтому корректно открывается в русской версии Excel. Скрипт также читает CSV с разделителем `,` или табуляцией.

Удалите строки пользователей, которым не нужно назначать 2FA. Не изменяйте заголовки, UID, логины и email. Сохраните и закройте файл.

### 2. Проверить CSV без изменений

Windows:

```powershell
python .\y360_per_user_2fa.py apply --file .\users_2fa_1234567_20260909_120000.csv --dry-run
```

macOS и Linux:

```bash
python3 y360_per_user_2fa.py apply --file ./users_2fa_1234567_20260909_120000.csv --dry-run
```

Проверяются:

- режим 2FA организации;
- структура и заголовки CSV;
- формат и уникальность UID;
- наличие каждого UID в текущем справочнике;
- соответствие UID, логина и email.

### 3. Включить персональную 2FA

После успешного `--dry-run` выполните:

```powershell
python .\y360_per_user_2fa.py apply --file .\users_2fa_1234567_20260909_120000.csv --verify
```

Скрипт потребует контрольную фразу, включит 2FA и создаст отчет `2fa_change_results_дата_время.csv`. Ключ `--verify` добавляет отдельный контрольный GET для каждого пользователя.

## Единый интерактивный режим

```powershell
python .\y360_per_user_2fa.py interactive --exclude-dismissed --exclude-disabled --exclude-robots --verify
```

Порядок работы:

1. Скрипт проверит режим организации и выгрузит CSV.
2. Откройте файл и удалите ненужные строки.
3. Сохраните и закройте CSV.
4. Вернитесь в терминал и нажмите Enter.
5. Скрипт повторно проверит режим, CSV и актуальный справочник.
6. Введите контрольную фразу.
7. Скрипт изменит 2FA и создаст отчет.

Без указания действия запускается тот же интерактивный режим:

```powershell
python .\y360_per_user_2fa.py
```

## Выключение персональной 2FA

Оставьте в CSV только нужных сотрудников и выполните сначала проверку:

```powershell
python .\y360_per_user_2fa.py apply --file .\users_2fa_1234567_20260909_120000.csv --state disable --dry-run
```

Затем реальное изменение:

```powershell
python .\y360_per_user_2fa.py apply --file .\users_2fa_1234567_20260909_120000.csv --state disable --verify
```

## Производительность и устойчивость

По умолчанию используются четыре параллельных запроса. Для осторожного первого запуска:

```powershell
python .\y360_per_user_2fa.py apply --file .\users_2fa_1234567_20260909_120000.csv --workers 1 --verify
```

Допустимый диапазон `--workers` — от 1 до 10. Публичная документация не фиксирует отдельный RPS-лимит для изменения персональной 2FA, поэтому без практического подтверждения не рекомендуется увеличивать значение выше 4.

При ответах `429`, `500`, `502`, `503`, `504` и сетевых сбоях скрипт выполняет до пяти повторов с увеличивающейся задержкой и учитывает числовой заголовок `Retry-After`.

## Коды завершения

- `0` — все операции успешны или `--dry-run` пройден;
- `1` — ошибка настройки, режима организации, файла или предварительной проверки;
- `2` — обработка завершена, но изменение подтверждено не для всех пользователей;
- `130` — выполнение прервано с клавиатуры.

## Ограничения и безопасность

- API не предоставляет массовый PATCH: выполняется отдельный запрос для каждого пользователя.
- Скрипт работает с одной организацией за запуск.
- Изменения не являются общей транзакцией: часть пользователей может быть обработана успешно, а часть — с ошибкой.
- `--verify` удваивает число пользовательских запросов, но дает более надежный итоговый отчет.
- Самостоятельно настроенная пользователем 2FA и обязательная персональная 2FA — разные состояния. Этот скрипт управляет именно обязательным признаком `is2faEnabled` в режиме `per_user`.
- Сначала используйте `--dry-run`, затем протестируйте на небольшой группе.
- Не применяйте `domain-enable` и `--logout-users` без согласованного окна изменений.
- Не используйте `--yes` вручную: он отключает контрольную фразу и предназначен только для контролируемой автоматизации.
